# timbreprobe — can timbre be measured and navigated?

[中文说明 / Chinese README](README.zh.md) · **Action guide:** [ROADMAP.md](ROADMAP.md)

This repository is the **gate experiment** for a larger research programme on
*inverse synthesizer patch synthesis*: mapping human intent (a text description
or a hummed melody) to a **structured synthesizer parameter set (a patch)**
rather than to audio.  Before investing in that whole system, two assumptions
have to hold, and Stage 0 tests exactly those:

* **H1 — perceptual monotonicity**: does an embedding distance between two
  sounds predict which one humans judge as more similar?  *(measured by the E1
  listening test; material is generated by this repo, results need listeners)*
* **H2 — navigability**: can a search algorithm reach a target sound by
  optimising an embedding distance over patch parameters, and is a learned
  *surrogate* fast enough and accurate enough to do it without rendering?
  *(measured by the E2 experiment; fully automated)*

Everything is built on a **differentiable subtractive synthesizer** (31
parameters, STFT-domain filtering) whose output feeds an **85-dim differentiable
DSP embedding**.  That makes patch → audio → embedding a single differentiable
graph, so "true gradient" navigation through the real renderer is available as
an oracle baseline.

**Headline result (smoke scale, 3.9k corpus, 48 targets):** H2 passes only
weakly.  True-gradient search does beat the retrieval start (median distance
ratio **0.845**, 95% CI [0.765, 0.938]), but it plateaus after ~15% and needs
~5.9k real renders.  Every surrogate-based search **lost** to the start
(1.44–2.12), and the surrogate's out-of-distribution rank correlation is only
τ≈0.39 — so the surrogate, not the search algorithm, is the bottleneck.  See
[Results](#results).

---

## What this is (and is not)

* It **is** a reproducible, CPU-runnable instrument for measuring whether a
  timbre embedding is (a) monotone w.r.t. human similarity and (b) usable as an
  optimisation objective.  The E2 experiment is fully automatic; the E1
  material is generated in one command and runs in a browser.
* It is **not** a patch generator, not a synth plugin, and not a perceptual
  model.  The bundled embedding is handcrafted DSP features — a deliberate
  *lower anchor*: a pretrained embedding (CLAP / MuQ) that cannot beat it on
  human similarity is not worth using.  Swapping the embedding is a
  single-module change (`timbreprobe/features.py`).
* The synthesizer is an *oracle for Stage 0*, not a product: filtering happens
  in the STFT domain (no filter phase/ringing) and the render protocol is a
  fixed C4 sustained note.  See [Limitations](#limitations).

## Quickstart

```bash
git clone https://github.com/Fengrru/timbreprobe && cd <REPO>
pip install -r requirements.txt        # or: pip install -e ".[report]"

python -m timbreprobe.cli sanity                  # correctness suite (~1 min, no data needed)
python -m timbreprobe.cli corpus --preset smoke   # build corpus + embeddings (~2-3 min)
python -m timbreprobe.cli e2     --preset smoke   # run the E2 experiment
python -m timbreprobe.cli plot   --run out/e2_smoke

python -m timbreprobe.cli e1     --preset smoke   # generate the listening test
python -m timbreprobe.cli e1-analyze --responses res_P01.json,res_P02.json
```

`--preset full` runs the same pipeline at paper scale (6.2k corpus, 128 targets,
120 optimiser steps).  Everything lands in `out/` (git-ignored): corpus,
embeddings, surrogate, result JSON, curves, figures.  A pre-computed smoke run
is committed under [`results/smoke/`](results/smoke/).

Hear the parameter space first: [`assets/demo/`](assets/demo/) contains the 16
anchor patches as 0.5 s wav files.

> **Threading note.** On the development machine (4-core Windows, CPU-only)
> multi-threaded torch was 2–5× *slower* than single-threaded for these tensor
> shapes.  The CLI therefore defaults to `torch.set_num_threads(1)`; override
> with `STAGE0_THREADS` if your machine behaves normally.  Render cost at
> B=64: ~2.3 s forward, ~7.1 s forward+backward (single thread).

## Results

### E3 — surrogate fidelity (patch → embedding regression)

| split | n | R² | cosine | distance Pearson | distance Kendall τ |
|---|---|---|---|---|---|
| val | 308 | 0.780 | 0.884 | 0.893 | **0.701** |
| test | 1119 | 0.510 | 0.719 | 0.725 | 0.482 |
| holdout anchors | 811 | 0.288 | 0.673 | 0.529 | **0.387** |

The *holdout* rows come from four anchor clusters deliberately excluded from
training.  Distance rank correlation (τ) is the metric that matters for search,
and it degrades sharply out of distribution.

### E2 — navigability (48 targets, half from held-out anchor clusters)

All methods start from the same point per target: the nearest *training* patch
in embedding space (i.e. Stage 1's retrieval initialisation).  Every number
below is therefore the value added **on top of retrieval**.  `ratio =
d_final / d_init` (median, bootstrap 95% CI); `renders` = real renders consumed.

| method | ratio | in-dist. | holdout | success@0.5 | renders |
|---|---|---|---|---|---|
| `retrieval_nearest` (= the start) | 1.000 | 1.000 | 1.000 | 0.06 | 0 |
| `retrieval_unigram64` (best of 64 random presets) | 1.393 | 1.646 | 1.341 | 0.00 | 0 |
| `grad_surrogate` | 2.119 | 2.633 | 1.900 | 0.02 | 48 |
| `grad_surrogate_trust` | 1.443 | 1.614 | 1.353 | 0.00 | 48 |
| `grad_reground` | 1.690 | 2.077 | 1.478 | 0.00 | 576 |
| **`grad_true`** (oracle) | **0.845** [0.765, 0.938] | 0.797 | 0.875 | **0.15** | 5856 |
| `cmaes_true` (sep-CMA-ES, same objective) | 0.961 [0.899, 1.000] | 0.948 | 0.961 | 0.08 | 21696 |

![E2 method comparison](results/smoke/figures/e2_ratios.png)
![E2 search trajectories](results/smoke/figures/e2_curves.png)

**Four conclusions.**

1. **H2 passes weakly.** Only true-gradient search beats the retrieval start,
   and the confidence interval excludes 1.0 — but the gain is ~15% median with
   15% of targets halving their distance, and the trajectory plateaus quickly
   (3.08 → 2.54 within ~15 steps and then flat).  Monotone local search cannot
   make the discrete jumps (waveform / octave switches) that some targets
   require.
2. **Gradient information is worth much more than population search here.**
   sep-CMA-ES spent 3.7× the renders (21 696 vs 5 856) and still scored worse
   (0.961 vs 0.845).
3. **The surrogate is the real bottleneck, not the optimiser.** All three
   surrogate-based variants ended *worse than the start*.  Strikingly, they do
   *worse* in-distribution (2.63) than on holdout targets (1.90): where the
   surrogate is confident but wrong, the optimiser gets exploited hardest.
   Until surrogate fidelity improves, "search freely on the surrogate" is not a
   viable Stage-1 design.
4. **Re-grounding alone does not rescue it.** Rendering every 20 steps and
   fine-tuning online moved 2.12 → 1.69; a plain trust region (no extra
   renders) did better in-distribution (2.63 → 1.61).

**Consequence for the plan:** before moving to a real synth (Vital) or the
humming modality, fix one of (a) the embedding (retrain with CLAP / MuQ and
re-check monotonicity with E1), or (b) the search space (train an autoencoder
on real presets and search the *legal latent manifold* instead of raw
parameters — this is what turns discrete jumps into continuous paths).

### E1 — perceptual monotonicity (material ready, needs listeners)

`python -m timbreprobe.cli e1` writes a self-contained
`listening_test.html` plus wav files and a separate answer key:

* a pool of 600 patches is rendered at 0.5 s and embedded, so listeners judge
  **exactly** the audio the distances were computed on;
* each trial plays a reference A and two options whose embedding distances to A
  fall in **different quantile bins** of the pool distance distribution
  (measured edges for the smoke pool: 7.18 / 10.26 / 14.05);
* the closer option's screen position is randomised; the page never contains the
  answer; responses download as JSON; `e1-analyze` reports agreement per
  distance-contrast level with Wilson intervals.

Pre-registered gate: the primary embedding must agree with listeners
significantly above chance overall **and** improve monotonically with contrast
strength; a pretrained embedding that fails to beat the handcrafted baseline is
rejected.

## How the pieces fit

```
patch u ∈ [0,1]^31
   │  synth.py        differentiable subtractive synth (osc → drive → filter → VCA → drive)
   ▼
audio [B, T]
   │  features.py     85-dim differentiable DSP embedding (log-mel, centroid, bandwidth,
   ▼                   soft rolloff, flatness, flux, slope, crest, band ratio, envelope
embedding z            stats, smooth ZCR, harmonic & odd/even ratios)
   ├─ surrogate.py    MLP u → z  (the accelerator; E3 measures it)
   └─ navigators.py   true-gradient / surrogate / re-grounded / sep-CMA-ES / retrieval
```

| module | role |
|---|---|
| `schema.py` | the 31-parameter schema; continuous ↔ normalised maps, soft-blend discrete dims, hardening, human-readable dumps |
| `synth.py` | the oracle renderer; also keeps the per-sample SVF reference implementation used by `sanity` |
| `features.py` | embedding + corpus normaliser (the swap point for CLAP / MuQ) |
| `corpus.py` | anchor-stratified sampling (sweeps / jitter / uniform / sparse), splits, persistence |
| `surrogate.py` | patch → embedding MLP, E3 fidelity metrics, save/load |
| `navigators.py` | the six search strategies + retrieval baselines + `PerceptualSpace` |
| `experiment_e2.py` | E2 orchestration, stratified reporting, artefact persistence |
| `e1_listening.py` | E1 material generation (triplets + HTML + key) and analysis |
| `plotting.py` | figures for an E2 run |
| `config.py`, `cli.py` | presets (`smoke`, `full`) and the command line |
| `sanity.py` (inside `cli`) | correctness suite: determinism, RMS, gradient finiteness/coverage, monotonicity of cutoff/resonance/slope, sep-CMA-ES on a sphere, spectral-filter vs. per-sample-SVF agreement |

## Engineering notes worth knowing

Each of these was measured, hit us, and is documented because anyone extending
this code will hit it too:

| finding | measurement | resolution |
|---|---|---|
| A per-sample IIR loop is unusable on CPU | 10 s forward / 60 s with backward per batch, independent of batch size | filter in the STFT domain using the analytic TPT-SVF magnitude response (~100× faster); response shape matches the per-sample reference (Spearman ρ = 0.996) |
| Multithreading was *slower* than single-threading | MLP step 65 ms (1T) vs 681 ms (4T); render 2.1 s vs 5.0 s; fwd+bwd 6.9 s vs 31.9 s | default to 1 thread (`STAGE0_THREADS` to override) |
| `torch.istft` backward produced non-finite gradients at the padded edges | reproduced at 0.4 s renders, absent at 0.05 s | hand-rolled overlap-add with a clamped window-envelope normaliser |
| `asin(sin(x))` triangle LFO has an infinite derivative at \|s\| = 1 | NaN in exactly the `lfo_rate` dimension (4/248 entries) | closed-form triangle `1 − 4·\|frac(φ+0.25) − 0.5\|` |
| Fixed-step Adam overshoots badly | lr = 0.05 pushed the true distance 3.08 → 5.29 within 5 steps with no recovery | per-target adaptive step + accept/reject (grow ×1.3, shrink ×0.5) |
| Numpy broadcasting to an [N, N, D] distance tensor thrashes memory | ~490 MB per call at N = 1200, three calls in a row | Gram-identity pairwise distances, allocate [N, N] only |

## Limitations

1. The embedding is handcrafted DSP features, **not** CLAP/MuQ; passing E2 on it
   is a necessary condition only.  Re-run E1/E2 after swapping the embedding.
2. Filtering is zero-phase and spectral: no filter ringing or self-oscillation,
   transients smoothed at the 16 ms analysis window.  Resonance does not sound
   like a real analog filter.
3. Output is RMS-normalised, so absolute loudness is not identifiable; with a
   single active source the source-level dimension is likewise unidentifiable
   (parameter recovery error is inflated accordingly, as expected).
4. Discrete parameters are softly blended, so "in-between" morphs exist that a
   real synth cannot produce; hardened parameter L1 is the stricter metric.
5. The render protocol is a 0.25 s sustained C4 note (no note-off, so release
   stages and slow LFOs are unidentifiable by design).
6. All timings come from a machine under heavy external load (throughput
   varied up to 5×); treat them as relative, not absolute.
7. The E2 numbers are a *smoke* run (3.9k corpus, 48 targets) — enough to
   invalidate the naive design, not enough to be the final word; `--preset
   full` is the paper-scale configuration.
